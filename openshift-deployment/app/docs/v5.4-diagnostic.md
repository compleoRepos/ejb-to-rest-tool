# v5.4 Diagnostic — Session Persistence & Rendering

## BUG 1 — Session Persistence
- Sessions stored in-memory Map via `session-store.ts` (SessionStore class)
- Persisted to `/tmp/compleo-sessions.json` on disk (survives HMR restarts)
- **Problem**: `/tmp` is cleared on server restart/deploy → sessions lost
- **Fix**: Migrate to DB table `compleo_sessions` using Drizzle ORM
- Client side: no localStorage persistence of sessionId → page refresh loses context
- **Fix**: Add localStorage persistence of sessionId + state

## BUG 2 — Data Rendering
- Compleo.tsx uses 5 separate steps with useState (no persistence)
- No mounted check on async setState calls
- No guards on nested data access (response.useCases vs response.data.useCases)
- **Fix**: Add mounted checks, guards, proper loading states

## BUG 3 — Generated Files Display
- generationResult stored in useState only
- File preview loads on click but no fallback for empty state
- **Fix**: Add guards and empty state messages

## BUG 4 — ZIP Loader
- Already fixed in previous versions (recursive scan in java-parser.ts)
- Need to verify with boa-realistic-ejb-project.zip
