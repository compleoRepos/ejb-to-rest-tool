§ 01 — Synthèse exécutive

Une plateforme bancaire en attente de sa modernisation.

Les 19 services BMCEDirect partagent une architecture EAI cohérente, structurée autour de quatre frameworks propriétaires. Leur modernisation peut être conduite en deux temps, avec un point de bascule technique clairement identifié.

FINDING/01 Atout stratégique

Cohérence architecturale forte

Les 19 services suivent un même pattern : EJB Stateless · UseCase pattern (BaseUseCase, @UseCase) · Envelope EAI · ValueObject. Cette homogénéité est un atout — la migration de l'un éclaire la migration des autres.

```
FINDING/02 Tier 0 prioritaire

Quatre frameworks à migrer en priorité

Les packages ma.eai.commons, ma.eai.ingdev.fwk, ma.eai.midw et ma.eai.boa.xbanking concentrent 1 411 imports cumulés. Leur migration en premier déverrouille les 19 services.

FINDING/03 Parallélisable

Services métier parallélisables

Une fois les frameworks portés, les 19 services sont indépendants entre eux — aucune dépendance horizontale détectée. Trois équipes peuvent migrer en parallèle six à sept services chacune en 12-16 semaines.

FINDING/04 Point d'attention

Dépendance forte à Envelope

176 imports répartis sur l'ensemble du portefeuille. Toute évolution du wrapper request/response EAI impactera 18 services sur 19. La migration de cette classe doit être traitée comme un événement de plateforme, pas comme un fix local.
```

§ 05 — Pattern d'appels typique

Comment une requête traverse la pile.

Reconstitution du pattern d'appels standard observé dans les 19 services. Comprendre ce flux est essentiel pour modéliser la transformation Spring sans rupture fonctionnelle.

Client→POST /service/bmcedirect
Requête XML/JSON wrappée selon le contrat EAI
```
XbankingServlet→Parser.parse(req)
Extraction du payload depuis l'Envelope d'entrée
Parser→Envelope envIn
Construction du wrapper request, en mémoire
XbankingService→BaseUseCase.run(envIn, envOut)
Dispatch vers le UseCase annoté @UseCase
UseCase Impl→EaiLog.info("traceId=...")
Trace d'audit en début de processing
UseCase Impl→SynchroneService.call("CBS_OP")
Appel synchrone au back-office via middleware
UseCase Impl→Envelope envOut
Construction de la réponse, sérialisation Parser.format
Erreur métier→throw FwkRollbackException
Rollback automatique sous @ContinueOrStartTransaction
```

Implication migration : chaque maillon a une cible Spring naturelle — Servlet → @RestController, Parser → Jackson, BaseUseCase → @Service, SynchroneService → OpenFeign, FwkRollbackException → @Transactional(rollbackFor). Le mapping est direct et reproductible.

Deux phases, une trajectoire claire.

8-12sem.

Migration des frameworks transverses (Tier 0)

Porter les 4 frameworks ma.eai.* en modules Spring Boot 3 indépendants. Chaque module est publié comme artefact Maven (groupId com.nexa.bmce) avec un contrat de compatibilité documenté.

nexa-commons (Envelope, Parser, utilities)

Migration séquentielle : commons → fwk → midw → xbanking. Chaque module produit des tests d'API qui serviront de contrats pour la Phase II. Une équipe socle de 3-4 ingénieurs senior.

§ 08 — Points de vigilance

Quatre risques, quatre mitigations.

R1

Cohérence cross-projet de la classe Envelope

Avec 176 imports répartis sur 18 services, toute évolution du contrat Envelope impacte la quasi-totalité du portefeuille. Sans gouvernance forte, on risque des incompatibilités cachées entre services migrés et non migrés pendant la phase de transition.

Mitigation — MigrationRegistry de COMPLEO trace les versions de chaque artefact migré et applique les remplacements aux dépendants. Tests de contrat (Pact / Spring Cloud Contract) sur l'API d'Envelope dès la première migration.
Impact
18/19 services
```
R2

Latence des connecteurs back-office (ma.eai.midw)

SynchroneService et Services appellent des SI cœur (CBS, comptabilité, Swift) avec des SLA hétérogènes. La transformation en clients Spring (OpenFeign) doit préserver les timeouts métier existants, sous peine de cascades de timeout en production.

Mitigation — Extraction préalable des paramètres timeout depuis le code legacy. Mapping 1-pour-1 vers configuration Resilience4j. Tests de charge sur environnement iso-prod avant bascule.
Impact
Performance
R3

Non-déterminisme de la génération LLM

COMPLEO utilise un LLM pour les transformations sémantiques complexes. Chaque exécution produit une variante du code Spring généré — les tests de compilation Maven montrent une stabilité variable sur les patterns de syntaxe (parenthèses multi-lignes, casts).

Mitigation — Fine-tuning du modèle sur dataset BMCE (2 052 paires extraites) en cours. Stabilisation attendue sur les patterns récurrents. Couche post-traitement déterministe (CompileAutoFixer) en filet de sécurité.
Impact
Productivité
R4

Sous-package xbanking volumineux et hétérogène

ma.eai.boa.xbanking concentre 573 imports mais couvre des sous-domaines très différents (vo, dto, service, entities, utils, madCore, ProduitsEpargne, monetique). Une migration monolithique de ce framework allongerait la Phase I et créerait un goulet d'étranglement.

Mitigation — Découpage par sous-package fonctionnel : nexa-xbanking-vo, nexa-xbanking-dto, nexa-xbanking-monetique, etc. Migration progressive avec releases successives au lieu d'un big-bang.
Impact
Calendrier
```
§ 09 — Glossaire

Vocabulaire technique partagé.

Envelope
Wrapper request/response du framework EAI BMCE. Encapsule header (métadonnées de routage, traceId, security) et body (payload métier). Sérialisé en XML ou JSON selon contrat.
UseCase
Pattern structurant : chaque opération métier = une classe annotée @UseCase héritant de BaseUseCase, avec une méthode run(envIn, envOut). Équivalent au pattern Command.
ValueObject
Classe de base de tous les DTOs métier. Sérialisable, immutable conceptuellement, transportée à travers les couches. Équivalent Java EE des Bean DTOs.
EaiLog / Log
Deux loggers distincts coexistent : EaiLog (framework EAI, applicatif) et Log (middleware, système). À factoriser en SLF4J + MDC pendant la migration.
FwkRollbackException
Exception déclencheant un rollback de transaction. Cible Spring : RuntimeException standard sous @Transactional avec rollbackFor explicite.
@ContinueOrStartTransaction
Annotation EAI pilotant la propagation transactionnelle. Cible Spring : @Transactional(propagation=REQUIRED).
SynchroneService
Connecteur d'appel synchrone vers un SI back-office (CBS, comptabilité, Swift). Bloquant. À migrer vers OpenFeign avec Resilience4j pour timeouts et circuit breakers.
DAG (Directed Acyclic Graph)
Graphe orienté sans cycle, représentant les dépendances entre projets. Permet le tri topologique qui donne l'ordre de migration optimal.
Tier de migration
Niveau dans le DAG. Tier 0 = projets sans dépendances entrantes (à migrer en premier). Tier N = projets dont toutes les dépendances sont en Tiers 0..N-1.
MigrationRegistry
Composant COMPLEO qui mémorise les migrations effectuées et applique automatiquement les remplacements de dépendances (imports + pom.xml) aux projets dépendants migrés ultérieurement.
